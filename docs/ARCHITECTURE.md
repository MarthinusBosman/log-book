# Architecture

Product name **Log-Book** (`log-book.app`; single constant in `src/lib/brand.ts`). A dropzone management platform
(manifest, tandems, staff, aircraft, gear, waivers, payments) plus a jumper logbook/wallet, shipped
from **one codebase** to two deployment targets.

## Deploy targets

| | Hosted (global) | Self-hosted (dropzone) |
|---|---|---|
| `DEPLOY_TARGET` (build time) | `cloudflare` | `bun` (default) |
| Adapter | `@sveltejs/adapter-cloudflare` (Workers + static assets) | `@sveltejs/adapter-node`, run with `bun build/index.js` |
| Database | Cloudflare D1 (binding `DB`) | `bun:sqlite` file (`DATABASE_PATH`, default `data/app.db`) |
| Migrations | `wrangler d1 migrations apply DB` | applied automatically on startup (drizzle migrator) |
| File storage (`STORAGE_DRIVER`) | `db` — chunked BLOBs in D1 (`file_blobs`); `r2` optional | `disk` (`UPLOADS_DIR`); `db` optional |
| Scheduled work | cron trigger → wrapper `scheduled()` → `POST /api/cron` | hourly `setInterval` from `init` in hooks |
| `INSTANCE_MODE` default | `global` | `dropzone` |
| Packaging | `scripts/deploy-cf.sh` ([DEPLOY.md](DEPLOY.md)) | `Dockerfile` + `docker-compose.yml` ([SELF_HOSTING.md](SELF_HOSTING.md)) |

`vite.config.ts` picks the adapter and injects `__DEPLOY_TARGET__` via `define`. Because it is a
build-time constant, `getDb()` in `src/lib/server/db/index.ts` dead-code-eliminates the unused
driver: the Worker bundle never contains `bun:sqlite` (a Vite plugin also fails the Cloudflare build
if anything imports `bun:*`), and the Bun bundle never references `cloudflare:workers`.

Note: SvelteKit 3 adapter-cloudflare no longer passes `platform.env`; bindings come from
`import { env } from 'cloudflare:workers'` (see `driver.d1.ts`). In `vite dev` the adapter provides
the same module backed by Miniflare, so `bun run dev:cf` uses the *local* D1 in `.wrangler/`.

## Data layer

* One Drizzle schema: `src/lib/server/db/schema.ts`; migrations in `/drizzle` (generated by
  `bun run db:generate`) are plain SQL usable by both D1 and bun:sqlite.
* Conventions: text ids (UUID), integer millisecond timestamps, snake_case, JSON as `text` with a
  typed `$type<>()`. Text ids matter for federation: rows can be synced between instances.
* The `Database` type is driver-agnostic (`BaseSQLiteDatabase<'sync' | 'async'>`). Always `await`
  queries. **Don't use interactive transactions** (D1 doesn't support them) — use `db.batch()` on D1
  or design idempotent write sequences.
* `hooks.server.ts` sets `event.locals.db`, then validates the session.

## Auth

* Hand-rolled Lucia-v3 pattern: random 160-bit token in an `HttpOnly; SameSite=Lax` cookie
  (`Secure` on https); DB stores `sha256(token)` as `sessions.id`. 30-day lifetime, sliding renewal
  when < 15 days remain.
* Passwords: WebCrypto PBKDF2-HMAC-SHA256, 100 000 iterations (the Workers ceiling), 16-byte salt,
  stored as `pbkdf2-sha256$<iter>$<salt>$<hash>` so the algorithm can be upgraded; verification
  reports `needsRehash` and `authenticate()` transparently upgrades old hashes.
* Password reset: single-use hashed token, 1 h expiry, resets sign out all sessions. Email goes
  through the `Mailer` interface (`src/lib/server/email`), console implementation for now.
* Account deletion (self-service, `/app/profile/delete`): personal data is deleted, dropzone records are kept and
  the `users` row becomes an anonymous tombstone; see `docs/DOMAIN.md` → account.ts.
* Authorisation: users are global; membership is `dropzone_members (dropzone_id, user_id, status)`
  and a member can hold **several roles** in `dropzone_member_roles` (owner, admin, manifest, staff,
  tandem_instructor, aff_instructor, instructor, coach, videographer, rigger, pilot, jumper). Roles map
  to capabilities (`ROLE_CAPABILITIES`); check with `requireCan()` — see `docs/DOMAIN.md`. The active
  dropzone is a cookie (`dz`) validated against memberships on every `/app` request.
* CSRF: SvelteKit's built-in origin check for form posts. Behind a proxy set `ORIGIN` (adapter-node).
* TODO before production: rate-limit login/signup/reset (Cloudflare rate-limit binding or a small
  SQLite-backed limiter), email verification, real mail provider.

## Federation

A jumper has **one global identity and logbook** on the hosted instance, while a dropzone may run
its own self-hosted instance and still let jumpers "Link global account". Code:
`src/lib/server/import/federation/` (`server.ts` global side, `client.ts` dropzone side,
`crypto.ts` WebCrypto helpers, `web.ts` route glue) and `src/lib/server/domain/federation.ts`
(outbox). No extra tables: it uses `instances`, `linked_accounts` and `federation_outbox`.

### Roles
* **Global instance** (`INSTANCE_MODE=global`): OAuth 2 authorization server (auth code + PKCE)
  and logbook system of record. Endpoints only exist in this mode (404 otherwise):
  `/.well-known/oauth-authorization-server`, `/oauth/authorize` (consent screen),
  `/oauth/token`, `/oauth/userinfo`, `/oauth/revoke`, `/api/federation/jumps`.
* **Dropzone instance** (`INSTANCE_MODE=dropzone`): OAuth client of the global instance;
  `/app/settings/linked-accounts(/callback)` and `/api/federation/flush`.

### 1. Instance registration (global → `/app/settings/federation`)
A dropzone owner/admin (or super admin) registers the instance: name, origin, redirect URI
(default `<origin>/app/settings/linked-accounts/callback`, must be on the origin). The global
instance creates an `instances` row and shows `client_id` (`dzc_…`) and `client_secret`
(`dzs_…`, 256-bit) **once**:

* `client_secret_hash` = `sha256:<b64url(sha256(secret))>` (secrets are random, so a fast hash
  is fine);
* `public_key_jwk` holds the global server's **own per-client token-signing key** as an `oct`
  JWK (`{kty:'oct', alg:'HS256', k}`) — never sent to the client. (The column was meant for an
  Ed25519 client key; HMAC over the shared secret replaced that, see §3.)
* The owner can rotate the secret, suspend, reactivate or revoke (revoking deletes all grants).

The dropzone stores `FEDERATION_GLOBAL_URL`, `FEDERATION_CLIENT_ID`, `FEDERATION_CLIENT_SECRET`
in env, or — when unset — enters them on its `/app/settings/federation`, which stores them in an
`instances` row with id `federation-self`, status `suspended` (so it can never act as a client of
that server) and the secret as `stored:<secret>` in `client_secret_hash` (this side must present
it). The page shows the URLs to register, tests the connection (metadata endpoint), outbox stats
and a *Sync now* button.

### 2. Linking an account (authorization code + PKCE S256)
1. Jumper on the dropzone instance clicks **Link global account** → state + verifier go into an
   `HttpOnly` cookie (`fed_link`, 10 min, path-scoped) → redirect to
   `GLOBAL/oauth/authorize?response_type=code&client_id=…&redirect_uri=…&scope=openid profile logbook:write&state=…&code_challenge=…&code_challenge_method=S256`.
2. The jumper signs in on the global instance and sees the consent screen (instance name + host,
   scopes). Unknown client / unregistered redirect URI → error page (never redirected); other
   errors are redirected back with `error=`.
3. *Allow* → redirect back with `code` — a stateless HMAC token (2 min, bound to client, user,
   redirect URI, scope and the PKCE challenge). **Single use**: redeeming creates/updates the
   grant with `linked_at` ≥ the code's issue time, and a code issued before the current grant is
   rejected.
4. The dropzone's callback exchanges the code at `/oauth/token` (client auth via HTTP Basic,
   **JSON body** — SvelteKit's CSRF guard rejects cross-origin form-encoded POSTs without a
   matching `Origin`), then calls `/oauth/userinfo` → `{sub, name, email, licence, association,
   association_number}`.
5. Dropzone side stores `linked_accounts(user_id, issuer = global URL, subject = global user id,
   refresh_token_enc = AES-GCM(sha256('slot-link:'+client_secret)), scopes, linked_at)` and sets
   `users.global_id`. Its existing load jumps are queued (backfill) and pushed right away.

Global side, the **grant** is a `linked_accounts` row with `issuer = 'instance:<instance id>'`,
`subject = user_id = global user`, `refresh_token_enc = sha256 hash` of the current refresh token,
`scopes`, `linked_at`, `last_sync_at`. Global users see their linked dropzones (with synced-jump
counts) on `/app/settings/linked-accounts` and can unlink (= delete the grant). Unlinking on the
dropzone side calls `/oauth/revoke` and clears the user's queue.

Tokens: access tokens are stateless HMAC tokens (10 min) and are rejected once the grant is gone;
refresh tokens are random, stored hashed, and **rotated** on every use.

### 3. Logbook sync (server-to-server, signed)
* `completeLoad()` writes the logbook entries and, in the same atomic batch, a
  `federation_outbox` row (`jump_upsert`, payload = jump snapshot) for every jumper with an
  outgoing link.
* The outbox is flushed to `GLOBAL/api/federation/jumps` in batches of 50:
  * opportunistically after every mutating `/app` request on a dropzone instance (a `handle` hook
    — one indexed query when nothing is due; runs after the response on Bun, awaited on Workers),
    e.g. right after manifest completes a load;
  * by `POST /api/federation/flush` (`Authorization: Bearer $FEDERATION_FLUSH_SECRET`, defaulting
    to the client secret; send `Content-Type: application/json`) from cron;
  * by *Sync now* on the settings page.
* Requests carry `x-slot-client-id`, `x-slot-timestamp` (±5 min) and
  `x-slot-signature = b64url(HMAC-SHA256(sha256(client_secret), "<ts>.<body>"))`. The global
  instance derives the same key from its stored hash. Each item names the global `sub`; it is
  accepted only if that user holds a grant for the instance with `logbook:write`.
* Global upsert is **idempotent** on `source_ref = fed:<instance id>:<dropzone jump id>`:
  `source='import'`, numbered after the jumper's global logbook, `location` + `signer_name` = the
  source dropzone's name, `verified` as sent, `dropzone_id` = the instance's dropzone if set.
  Updates overwrite; `jump_delete` removes.
* Per-item results; failures get exponential backoff (1, 2, 4 … min, max 6 h) with `last_error`
  shown on the settings page. Items of users who unlinked are dropped.

### 4. Failure modes and limits
Offline dropzones keep working; the outbox retries. Revoking the grant (either side) stops sync;
both sides keep their copies. Known gaps: the HMAC key is derivable from the stored secret hash
(a global DB leak allows forging pushes until secrets are rotated); single-use codes rely on grant
timestamps rather than a code table; no pull direction yet (licence/currency from global);
edits/deletes of synced jumps on the dropzone aren't queued (only load completion is).

## Domain layer

Schema, vocabulary and services for every feature are documented in [`DOMAIN.md`](DOMAIN.md).
Uploads go through a `Storage` interface (`src/lib/server/storage/`), chosen by `STORAGE_DRIVER`:
`disk` (bun default), `db` (Cloudflare default: bytes in the `file_blobs` table split into 512 KB
parts — D1 caps a row at ~2 MB; written one part per statement and cleaned up on failure, read part
by part) or `r2` (binding `FILES`, untested). Metadata always lives in `files`. Size limits: images
5 MB, PDFs/imports 10 MB (`maxBytesFor`); avatar/dropzone-photo inputs downscale client-side first
(`src/lib/client/resize-image.ts`).

## Security headers and ops

* CSP comes from SvelteKit's `csp` option in `vite.config.ts` (`mode: 'auto'`: per-request nonce
  for the inline hydration script; `style-src 'unsafe-inline'` because Svelte/Tailwind use style
  attributes; `img-src` allows `data:`/`blob:`/`https:`; `frame-ancestors 'self'`). No
  `form-action`: the OAuth consent form redirects to the linking dropzone's origin.
* `hooks.server.ts` adds Referrer-Policy, Permissions-Policy (geolocation/clipboard/share = self,
  everything else off), X-Frame-Options, COOP, HSTS on https, and a `default-src 'none'; sandbox`
  CSP on non-HTML responses except PDFs (sandbox breaks browser PDF viewers).
* `GET /api/health` → version (`__APP_VERSION__` = package version + git sha), target, mode, DB status.
* `POST /api/cron` (`src/lib/server/housekeeping.ts`): expired sessions/reset tokens, orphaned blob
  chunks, federation outbox flush (dropzone mode). Auth: in-isolate token from the Worker's
  `scheduled()` (`scripts/cf-postbuild.ts`) or `Bearer $CRON_SECRET`.

## Frontend

* SvelteKit 3 + Svelte 5 runes, SSR everywhere, forms work without JS (`use:enhance` progressive).
* Tailwind v4 via `@tailwindcss/vite`; design tokens in `src/app.css` (`@theme` + CSS variables
  that flip between dark — the default — and light). Theme is a cookie read in `hooks.server.ts`
  so there's no flash on load.
* Own UI primitives in `src/lib/ui` (no component library). Inter is self-hosted via
  `@fontsource-variable/inter`.
* Navigation is declared in `src/lib/nav.ts` (staff vs jumper). `/app/[section]` renders
  placeholders until each module is built; staff sections are role-gated.
* Imports use Node subpath imports (`#lib/...` with explicit `.ts`/`.svelte` extensions) — the
  SvelteKit 3 replacement for `$lib`.
